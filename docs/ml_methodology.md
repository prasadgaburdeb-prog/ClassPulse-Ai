# ClassPulse AI — Machine Learning Methodology & Governance (v2.0)

## 1. Predictive Philosophy: Academic vs. Financial Risk Separation

Per SRS requirements **ML-027, ML-028, and ML-029**, ClassPulse AI strictly decouples academic exam performance from student tuition and fee payment statuses.

### Ethical Decoupling
Treating unpaid tuition fees as a direct penalty in academic success forecasts introduces severe socioeconomic bias. In ClassPulse AI:
- **Academic Model:** Predicts pass probability using only academic and attendance variables.
- **Financial Assessment:** Operates as an independent administrative ledger assessment (`Clear`, `Moderate Dues`, `High Financial Due`).

---

## 2. Feature Vector Definition

The Random Forest model consumes an input feature vector $X \in \mathbb{R}^5$ containing:

1. **Mock Exam Score ($x_1$):** Average score scaled to a normalized $[0, 100]$ basis.
2. **Attendance Rate ($x_2$):** Classroom attendance percentage $[0, 100]$.
3. **Classes Attended ($x_3$):** Absolute count of physical/virtual sessions attended.
4. **Attendance Trend ($x_4$):** Velocity of attendance $(\Delta \text{Rate} = \text{Rate}_{\text{recent}} - \text{Rate}_{\text{prior}})$.
5. **Course Rigor Index ($x_5$):** Multiplier reflecting examination difficulty:
   - JEE Advanced: $1.25$
   - NEET: $1.20$
   - General / Other: $1.00$
   - Foundation (Class 9-10): $0.90$

---

## 3. Model Architecture, Benchmark Provenance & Transparency (ML-005, ML-008, ML-011, FR-ML-01, FR-ML-02)

### Model Architecture
The ML predictor is implemented as a single **`RandomForestClassifier`** (Scikit-learn) with `n_estimators=150`, `max_depth=6`, `min_samples_split=4`, and `class_weight="balanced"`.
- It is a single decision-tree classifier; it does not combine multiple distinct model families (FR-ML-01).
- No secondary calibration wrappers (e.g. `CalibratedClassifierCV`) or stacking layers are applied to the base model.

### Benchmark Model Provenance
The base model version is **`v2.1.0-benchmark`**, trained on a synthetic academic benchmark dataset ($N = 1,200$) with a stratified 80/20 train/test split.

> [!IMPORTANT]
> The system explicitly labels this baseline model as `synthetic_benchmark` across the user interface, API responses (`provenance`, `is_synthetic`), and exported PDF reports (FR-ML-03).
> 
> All metrics reported below are **synthetic benchmark metrics** computed on generated demonstration data. They do **not** represent verified real-world institutional outcomes (FR-ML-02).
> Claims of validated real-world accuracy or production readiness require reproducible evaluation on verified centre cohort data using an approved evaluation protocol (FR-ML-04).

### Synthetic Benchmark Evaluation Metrics:
- **Synthetic Held-Out Test Accuracy:** $74.2\%$
- **Synthetic F1 Score:** $79.3\%$
- **Synthetic ROC-AUC Score:** $82.8\%$
- **Synthetic Brier Score Loss:** $0.174$
- **Synthetic 5-Fold Stratified Cross-Validation:** $80.7\% \pm 4.26\%$

## 4. Retraining Engine & Validation Gates (ML-015 to ML-020)

Centres can retrain the Random Forest model on their own historical cohorts. Before a newly retrained candidate model replaces the active model, it must pass three mandatory validation gates:

1. **Sample Size Gate (ML-017):** Requires at least $30$ verified student records with logged mock scores and actual examination outcomes.
2. **Class Balance Gate (ML-017):** Must contain at least $5$ verified pass instances and $5$ verified fail instances.
3. **Performance Gate (ML-020):** Must achieve a held-out test accuracy of $\ge 60\%$. If the candidate model fails, the engine automatically rolls back to the previous benchmark model without service interruption.

---

## 5. Strict Data Integrity: No Data Fabrication (DATA-018, ML-023)

In accordance with the SRS, ClassPulse AI **never** fabricates missing student information:
- If a spreadsheet lacks fee information, no default fee obligations (e.g. ₹20,000) are created.
- If a spreadsheet lacks attendance logs, no fake daily attendance records are synthesized.
- If mock scores are missing, the prediction is transparently flagged with `is_tentative = True`, `is_incomplete = True`, and `data_status = "incomplete_missing_mock_scores"`.

---

## 6. Human-in-the-Loop Review & Decision Governance (ML-009)

In accordance with SRS requirement **ML-009**, machine-learning outputs are strictly governed by human review:

1. **Decision Support Exclusively:**
   Predictions generated by ClassPulse AI are statistical indicators designed solely to assist educators, mentors, and academic administrators in prioritizing pedagogical guidance.
2. **Prohibition of Automated Adverse Actions:**
   Under no circumstances may a student be de-enrolled, barred from examinations, penalized financially, or denied institutional services based solely or primarily on an automated ML risk classification.
3. **Mandatory Faculty Verification:**
   High-risk flags (`High Risk of Failing`) must trigger a human consultation between the course instructor and student before any remedial or intervention plan is enacted.
4. **Appeals & Incomplete Data Review:**
   Whenever a prediction is marked `is_tentative = True` due to missing mock test scores or incomplete attendance sheets, administrators must verify raw physical attendance and diagnostic exam records before relying on the risk tier.

## 7. Real-World Academic Data Validation Protocol (ML-006, ML-007, ML-008)

### Current Validation Status: BLOCKED Pending Institutional Data
As specified in SRS v4.0 (Section 12), live institutional student outcome data from partner coaching institutions is not currently licensed or released for model evaluation. Consequently:
- Requirements **ML-006**, **ML-007**, and **ML-008 (real-world validation)** remain formally **BLOCKED** rather than falsely simulated.
- Current baseline evaluation metrics are strictly documented as **synthetic benchmark metrics** ($N=1,200$) and must not be cited as real-world clinical performance.

### Specification for Authorized Real-World Evaluation:
When authorized multi-year institutional student cohorts become available:
1. **Leakage-Resistant Cohort Split (ML-006, ML-007):**
   - Training and validation sets must be partitioned chronologically (e.g. train on 2023–2024 academic cohorts, test on 2025 cohorts) or by distinct branch campuses.
   - Random cross-sectional train/test splits that shuffle students within the same classroom term are prohibited to prevent temporal target leakage.
2. **Baseline Benchmarks:**
   - The Random Forest model must be compared against a majority-class predictor and a standard logistic regression baseline.
3. **Class-Sensitive Metrics (ML-008):**
   - In competitive examinations where fail rates often exceed pass rates, evaluation must report class-specific precision, recall, F1, ROC-AUC, Brier score loss, and full confusion matrices.
